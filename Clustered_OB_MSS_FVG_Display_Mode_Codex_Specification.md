# Follow-up Codex Specification — Cluster Display Modes

## Purpose

Modify the standalone `Clustered_OB_MSS_FVG.pine` indicator so that historical cluster detection remains intact while chart visualization becomes usable for discretionary historical review.

The current implementation can render many historical clusters simultaneously, producing severe visual saturation on intraday MES charts.

The required change is therefore a **visualization-layer change**, not a change to the underlying detection or association model.

Add a user-facing **Display Mode** with:

- `Latest Cluster` — default
- `All Clusters`

This indicator remains standalone and is not part of the AI Futures Trading Lab.

---

## 1. Core Principle

Keep:

```text
Detection / validation / state
            ≠
Visualization
```

The indicator must continue to detect clusters using the existing causal model:

```text
MSS
 ↓
MSS-producing displacement
 ↓
displacement-anchor OB
 ↓
FVG generated by same displacement
 ↓
cluster validation
```

Do not alter this logic merely to reduce the number of objects displayed.

The display layer decides which already-confirmed clusters are visible.

---

## 2. New User Input

Add:

```text
Display Mode
```

with:

```text
Latest Cluster
All Clusters
```

Default:

```text
Latest Cluster
```

Use an appropriate Pine input such as:

```pine
input.string(
    "Latest Cluster",
    "Display Mode",
    options = ["Latest Cluster", "All Clusters"]
)
```

The exact implementation may use constants or equivalent Pine-supported syntax.

---

## 3. Latest Cluster Mode

When:

```text
Display Mode = Latest Cluster
```

only the most recently confirmed cluster should be visible.

When a new cluster is confirmed:

1. Remove the previous displayed cluster's visual objects.
2. Keep the underlying detection/state architecture intact.
3. Render the new cluster.
4. Mark the new cluster as the currently displayed cluster.

The latest cluster consists of:

- OB box;
- FVG box;
- MSS line;
- MSS label.

No visual objects from older clusters should remain visible.

---

## 4. All Clusters Mode

When:

```text
Display Mode = All Clusters
```

retain the existing behavior of rendering all retained clusters subject to the existing object/state limits.

The current maximum retained cluster count remains:

```text
100
```

unless there is a separate implementation reason to change it.

Do not use this display-mode change as a reason to redesign cluster storage.

---

## 5. Display Mode Must Not Affect Detection

Do not implement Latest Cluster mode by changing the detection rules to only detect the latest cluster.

Instead:

```text
Detect clusters according to existing rules
        ↓
Store validated clusters
        ↓
Apply display policy
```

The same historical dataset must produce the same detected clusters regardless of display mode.

Only the rendered objects should differ.

---

## 6. Input Recalculation

TradingView recalculates the script when inputs change.

Therefore:

### Latest Cluster

Only the most recent confirmed cluster should be rendered.

### All Clusters

All retained eligible clusters should be rendered.

Do not allow stale visual objects from a previous display mode to survive recalculation.

---

## 7. Rendering Architecture

Separate:

```text
Cluster detection
       ↓
Cluster storage
       ↓
Display policy
       ↓
Rendering
```

Avoid duplicating the detection algorithm for the two display modes.

For Latest Cluster:

```text
new validated cluster
        ↓
remove previous displayed visuals
        ↓
render new cluster
```

For All Clusters:

```text
new validated cluster
        ↓
render it normally
```

---

## 8. Object Lifecycle

The existing visualization objects remain:

- `box`
- `line`
- `label`

Latest Cluster mode should visually contain only the current cluster's:

- OB box;
- FVG box;
- MSS line;
- MSS label.

Do not delete logical cluster state merely because its visual objects are hidden.

All Clusters mode should preserve the current lifecycle and cleanup policy.

---

## 9. Extension and Mitigation

Do not change existing extension semantics.

### Extend OFF

OB and FVG end at their natural boundaries.

### Extend ON

OB and FVG continue through the current bar.

### Extend + Extend Until Mitigated

Each zone stops independently on its first post-creation touch.

Do not change mitigation semantics.

A zone is mitigated on the first bar after cluster creation whose high-low range intersects the zone.

The cluster becomes fully mitigated after both zones have been touched.

Display mode must not reset or alter mitigation state.

---

## 12. Display Mode Acceptance Tests

### Test 1 — Default

Set:

```text
Display Mode = Latest Cluster
```

Expected:

Only the most recent confirmed cluster is visible.

### Test 2 — Multiple historical clusters

Load a historical MES range containing several valid clusters.

Expected:

Only the latest confirmed cluster is visible.

No older OB/FVG/MSS drawings remain visible.

### Test 3 — New cluster replaces previous display

Using Bar Replay:

1. Confirm cluster A.
2. Confirm cluster B later.

Expected:

After B is confirmed:

- A's visual objects are removed.
- B's OB, FVG, MSS line, and label are visible.

### Test 4 — Latest cluster after time-window close

Create a valid cluster inside the configured time window.

Continue replay outside the window.

Expected:

The latest cluster remains visible according to extension/mitigation settings.

### Test 5 — Extension

With Latest Cluster:

- Extend OFF → natural boundaries.
- Extend ON → zones extend through current bar.
- Extend Until Mitigated → each zone stops independently after its first post-creation touch.

### Test 6 — All Clusters

Set:

```text
Display Mode = All Clusters
```

Expected:

All retained clusters become visible.

Their detection results must be identical to Latest Cluster mode.

### Test 7 — Mode equivalence

Run the same historical range twice:

- Run A: Latest Cluster
- Run B: All Clusters

Expected:

The latest cluster in Run B must be identical to the cluster displayed in Run A:

- same direction;
- same MSS bar;
- same MSS level;
- same OB;
- same FVG;
- same creation bar.

Display mode must not affect detection.

### Test 8 — Input recalculation

Start with All Clusters and change to Latest Cluster.

Expected:

The script recalculates and only the latest cluster is visible.

No stale objects remain.

### Test 9 — Reverse recalculation

Start with Latest Cluster and change to All Clusters.

Expected:

All retained clusters become visible.

### Test 10 — Visible range

Pan and zoom without changing symbol, timeframe, data, or settings.

Expected:

The latest cluster does not change.
