# Follow-up Codex Specification — Displacement-Linked Cluster Association

## 1. Purpose

This document is a follow-up implementation specification for the standalone:

`Clustered_OB_MSS_FVG.pine`

It is based on the implementation review of the current Pine script, README, and validation notes.

The current indicator has a sound overall structure, but its central association rule needs to be strengthened:

> An OB, MSS, and FVG must belong to the same directional displacement event.

The next implementation revision must therefore make **displacement identification explicit** and associate the OB and FVG with that displacement rather than merely finding compatible components inside a broad event envelope.

This remains a standalone TradingView indicator.

It is **not part of the AI Futures Trading Lab**.

---

# 2. Problem Identified in Current Implementation

The current implementation performs the conceptual sequence:

```text
Confirmed swing
      ↓
MSS
      ↓
find last opposing candle
      ↓
search event envelope for FVG
      ↓
cluster
```

The main weakness is that the FVG search can find a qualifying FVG somewhere inside the 12-bar association envelope without proving that the FVG was generated by the displacement that actually caused the MSS.

The current implementation also identifies the OB as the nearest opposing candle before the MSS. This is deterministic and documented, but it does not explicitly establish that this candle is the anchor of the displacement responsible for the swing break.

The revision must change the association logic rather than merely reducing the 12-bar limit.

---

# 3. Required Conceptual Flow

The revised logic must follow:

```text
Confirmed swing
      ↓
Identify displacement that breaks the swing
      ↓
Identify OB anchoring that displacement
      ↓
Identify FVG generated by that displacement
      ↓
Verify same direction + same delivery event
      ↓
Create cluster
```

The implementation must not construct a cluster simply because three individually valid components happen to occur within the same broad time/price neighborhood.

---

# 4. MSS Definition

Retain the existing confirmed-swing model.

Use:

```pine
ta.pivothigh()
ta.pivotlow()
```

with the configurable:

```pine
MSS Swing Length
```

A bullish MSS requires a **confirmed candle close above the latest unbroken confirmed swing high**.

A bearish MSS requires a **confirmed candle close below the latest unbroken confirmed swing low**.

The implementation must remain close-confirmed.

Do not introduce:

- wick-only MSS;
- future-bar inspection;
- `lookahead_on`;
- retrospective swing manipulation.

Each confirmed swing should be broken at most once.

---

# 5. Explicit Displacement Identification

This is the main change.

When an MSS occurs, the code must identify the **directional displacement leg responsible for the break**.

For a bullish MSS:

```text
bearish/opposing structure
        ↓
bullish displacement
        ↓
close above confirmed swing high
        ↓
bullish MSS
```

For a bearish MSS:

```text
bullish/opposing structure
        ↓
bearish displacement
        ↓
close below confirmed swing low
        ↓
bearish MSS
```

The implementation must define displacement deterministically.

Do not use discretionary visual interpretation.

At minimum, displacement identification must establish:

1. the direction of the move;
2. the bars belonging to the move;
3. the bar or leg that actually produces the MSS close;
4. the valid structural origin immediately preceding that displacement.

The implementation must document the exact deterministic rule used.

---

# 6. Displacement Event Boundary

The existing 12-bar maximum may remain as a **safety bound**, but it must no longer be the primary mechanism for establishing component association.

The primary boundary is the actual displacement event.

A cluster must not use:

```text
FVG A
   +
OB B
   +
MSS C
```

merely because:

```text
A, B, and C
```

fall within 12 bars.

Instead:

```text
OB
 ↓
displacement
 ↓
FVG produced by displacement
 ↓
MSS produced by displacement
```

must be demonstrably one event.

If a candidate cannot establish this relationship, discard it.

---

# 7. Order Block Association

For a bullish displacement:

- identify the opposing candle/leg immediately anchoring the displacement;
- that candle becomes the bullish OB.

For a bearish displacement:

- identify the opposing candle/leg immediately anchoring the displacement;
- that candle becomes the bearish OB.

The implementation must not simply search backward from the MSS and select an arbitrary opposing candle.

The selected OB must be the anchor of the displacement that caused the MSS.

The full candle high-to-low range remains the OB zone.

---

# 8. FVG Association

The FVG must be generated by the same displacement that produces the MSS.

Standard definitions remain:

### Bullish

```text
candle 1 high < candle 3 low
```

### Bearish

```text
candle 1 low > candle 3 high
```

Additional requirements:

1. FVG direction must equal MSS direction.
2. The FVG must occur inside the identified displacement leg.
3. The FVG must be temporally downstream from the displacement origin.
4. The FVG must not be an unrelated older gap that merely falls inside the maximum association window.
5. If multiple qualifying FVGs are produced by the same displacement, apply one deterministic selection rule and document it.
6. Do not search the entire 12-bar envelope indiscriminately.

The implementation must explicitly prevent this:

```text
OB
 |
 |      unrelated FVG
 |
 |            displacement
 |                 ↓
 |                 MSS
```

from becoming one cluster.

---

# 9. Multiple FVGs

If a single displacement produces multiple qualifying FVGs, do not choose one arbitrarily based on a broad historical search.

Use a deterministic rule.

Preferred rule:

> Select the FVG directly associated with the displacement sequence that produces the MSS, using the earliest qualifying FVG within that displacement unless the implementation demonstrates a stronger deterministic causal relationship.

Document the selected rule in both the code comments and README.

The important requirement is reproducibility.

---

# 10. Candidate State Machine

The state machine should represent real detection stages rather than simply naming intermediate assignments.

Recommended flow:

```text
NO_CANDIDATE
      ↓
MSS_DETECTED
      ↓
DISPLACEMENT_IDENTIFIED
      ↓
OB_IDENTIFIED
      ↓
FVG_IDENTIFIED
      ↓
CLUSTER_VALIDATED
      ↓
CLUSTER_ACTIVE
      ↓
CLUSTER_MITIGATED
```

A state transition must represent an actual condition being established.

Do not mark:

```text
DISPLACEMENT_IDENTIFIED
```

unless the code has actually identified the displacement according to the deterministic rule.

Incomplete candidates must be discarded.

---

# 11. Temporal Constraints

Retain a maximum association safety bound of 12 bars unless implementation testing demonstrates that a different documented value is required.

However:

> The 12-bar limit is a guardrail, not the association definition.

The actual event boundary is determined by the displacement.

If the displacement cannot be established inside the maximum bound, discard the candidate.

Do not allow a later displacement to inherit an earlier OB or FVG.

---

# 12. Opposing Candle Cancellation

The current documentation states that a direction-opposing candle before a pending FVG cancels the candidate.

Retain this principle where appropriate.

The purpose is to prevent the system from silently stitching separate directional legs together.

Example:

```text
OB
 ↓
bullish movement
 ↓
candidate FVG
 ↓
bearish interruption
 ↓
bullish movement
 ↓
MSS
```

The implementation must not automatically treat all of this as one uninterrupted bullish displacement.

If the deterministic displacement definition considers the interruption to terminate the event, discard the candidate and require a new displacement event.

Document the exact rule.

---

# 13. Time Window

Keep the existing time-window behavior.

User inputs:

- Use Time Window
- Start Time
- End Time
- Time Zone

The MSS/qualifying event must occur inside the configured window.

The time window is a **qualification filter**, not a rendering filter.

A cluster created inside the window remains active after the window closes according to the extension/mitigation settings.

Retain:

- half-open interval;
- equal start/end = all day;
- end earlier than start = overnight window;
- explicit IANA timezone;
- historical DST behavior.

---

# 14. Mitigation

No conceptual change required.

Retain:

> A zone is mitigated on the first bar after cluster creation whose high-low range intersects that zone.

Do not allow the formation bar to immediately mitigate its own newly created zone.

Retain independent OB and FVG mitigation state.

The cluster becomes fully mitigated after both zones have been touched.

---

# 15. Extension

Retain current behavior:

### Extend OFF

OB and FVG terminate at their natural source/formation boundaries.

### Extend ON

Both zones extend through the current bar.

### Extend + Extend Until Mitigated

Each zone stops independently on its first post-creation touch.

---

# 16. Historical Integrity

This remains a historical validation indicator, not a trading strategy.

The implementation must continue to use:

```pine
indicator(...)
```

and must not use:

```pine
strategy(...)
```

Do not add:

- Strategy Tester logic;
- entries;
- exits;
- stop losses;
- targets;
- P&L;
- position sizing;
- trade statistics;
- automated execution;
- alerts;
- AI logic.

Historical bars must be processed sequentially.

A cluster must not appear until all information required to establish the cluster was actually available.

---

# 17. Realtime / Historical Consistency

Use identical structural logic for:

- historical bars;
- realtime bars.

No future-bar inspection.

No retrospective reconstruction.

No `lookahead_on`.

No visible-range dependency.

Changing chart zoom or visible history must not change already-established cluster results.

# 18. Required New Validation Tests

The existing tests remain valid, but the following tests are mandatory additions.

## Test A — Unrelated FVG inside event envelope

Construct:

```text
OB
 ↓
valid bullish FVG A
 ↓
additional candles
 ↓
bullish displacement
 ↓
MSS
```

Expected:

The cluster must use only an FVG that belongs to the displacement event according to the deterministic association rule.

It must not simply select FVG A because it is inside the 12-bar envelope.

---

## Test B — Two FVGs, only one belongs to displacement

Construct two valid bullish FVGs:

```text
OB
 ↓
FVG A
 ↓
unrelated movement
 ↓
displacement
 ↓
FVG B
 ↓
MSS
```

Expected:

FVG A must not be borrowed by the MSS event.

FVG B should be selected if it satisfies the defined displacement relationship.

---

## Test C — Unrelated OB inside event envelope

Construct:

```text
OB A
 ↓
bullish movement
 ↓
OB B
 ↓
bullish displacement
 ↓
MSS
```

Expected:

The implementation must select the OB that anchors the actual displacement, not an arbitrary older OB.

---

## Test D — Interrupted displacement

Construct:

```text
bullish displacement
 ↓
meaningful opposing interruption
 ↓
bullish continuation
 ↓
MSS
```

Expected:

The implementation must follow the documented event-boundary rule and must not silently combine separate legs.

---

## Test E — Same envelope, different displacement

Construct two directional delivery events inside 12 bars.

Expected:

Components from the first event cannot be combined with the MSS from the second event.

---

## Test F — No qualifying FVG

Construct a valid MSS and OB but no FVG belonging to the displacement.

Expected:

No cluster is rendered.

The OB must not appear independently.

The MSS must not appear independently.

---

## Test G — No qualifying OB

Construct a valid MSS and FVG but no valid displacement-anchoring OB.

Expected:

No cluster is rendered.

# 24. Codex Execution Prompt

Implement the follow-up revision to the standalone `Clustered_OB_MSS_FVG` Pine indicator.

The current implementation has a central association weakness: it detects MSS, then searches backward for the nearest opposing candle and searches the broader 12-bar event envelope for a qualifying FVG. This does not sufficiently prove that the OB and FVG belong to the displacement that actually caused the MSS.

Revise the implementation so the causal flow is:

```text
confirmed swing
    ↓
MSS
    ↓
identify MSS-producing displacement
    ↓
identify displacement-anchor OB
    ↓
identify FVG generated by same displacement
    ↓
validate one directional event
    ↓
create cluster
```

Requirements:

- Keep this as a standalone Pine v6 `indicator()`.
- Do not convert it to `strategy()`.
- Do not add Strategy Tester logic.
- Do not add entries, exits, SL, TP, P&L, trade statistics, alerts, automation, AI, or broker logic.
- Preserve confirmed-swing MSS detection.
- Preserve the user-facing time-window controls and semantics.
- Preserve extension and mitigation behavior.
- Preserve historical/realtime consistency.
- Preserve no-lookahead behavior.
- Keep the 12-bar value as a conservative maximum association bound, but do not use it as the primary causal association mechanism.
- Implement explicit deterministic displacement detection.
- Make the selected OB the anchor of the displacement that caused the MSS.
- Make the selected FVG originate from that same displacement.
- Prevent unrelated older FVGs from being selected merely because they fall inside the 12-bar envelope.
- Prevent unrelated older OBs from being selected merely because they fall inside the 12-bar envelope.
- Define and document the exact deterministic rules for displacement start/end, OB anchoring, FVG association, multiple FVG selection, and opposing interruptions.
- Make the state machine reflect actual detection stages.
- Add tests for unrelated FVGs, multiple FVGs, unrelated OBs, interrupted displacement, separate events inside the same envelope, missing FVG, and missing OB.
